# grasp_init — 파지 초기자세

에피소드를 "손이 이미 캡을 잡은 상태"에서 시작시켜 탐색을 줄인다.

접근·파지를 찾는 데만 1900 epoch 가까이 쓰고 있었고 (Turn 런: 인정 접촉이
3.4 에 도달한 게 epoch 1924), 그 구간은 매 런마다 똑같이 반복된다. 회전
설계를 비교하려는데 앞의 1900 epoch 이 매번 끼어 있으면 실험 한 번이 너무
비싸다.

## 왜 관측이 아니라 리셋인가

파지 정답을 넣는 자리는 세 곳이고 비용이 다르다.

    관측에 추가      차원이 바뀜 -> warm start 불가, 매번 재학습.
                     정책이 "참조 자세를 해석하는 법"도 배워야 해서
                     오히려 어려워질 수 있다.
    보상에 추가      관측 불변 -> warm start 가능. 다만 기존 항들과
                     또 하나의 균형 문제가 생긴다.
    리셋 초기자세    정책도 관측도 보상도 안 건드린다. 탐색 구간을
                     통째로 건너뛴다.  <-- 이 폴더

## 구성

    poses/*.json          관절각 스냅샷. capture_pose.py 가 쓴다
    reference_pose.py     로딩 + 환경에 적용. 환경이 import 하는 유일한 파일
    capture_pose.py       돌고 있는 정책에서 잘 잡힌 프레임을 떠서 저장

## 환경변수

    CAP_GRASP_INIT_POSE   poses/ 안의 json 경로. 비우면 기능 꺼짐
    CAP_GRASP_INIT_FRAC   이 자세로 시작할 환경 비율 (0~1, 기본 0.5)
    CAP_GRASP_INIT_NOISE  관절각에 더할 가우시안 노이즈 rad (기본 0.05)

## 비율을 1.0 으로 두지 말 것

전부를 같은 자세에서 시작시키면 그 자세에서만 동작하는 정책이 된다. 지금
학습은 RESAMPLE_WRIST=1 로 손목 위치를 매번 새로 뽑아 초기 조건을 넓히고
있는데, 파지까지 고정하면 그 다양성이 사라진다. 절반은 기존대로 두고 절반만
잡은 상태에서 시작하는 것이 기본값인 이유다.
