## 1. 좌표계·순서 규약 (먼저 확정할 것)

### 1.1 월드 프레임
학습에서 **RB5 베이스(link0)가 월드 원점, 단위 자세**다. 따라서 아래 모든 위치·자세는
**로봇 베이스 좌표계**로 계산하면 된다. z가 위.

### 1.2 텀블러 배치 (지그 상수)
- 텀블러 원점(바닥 중심): 월드 `(0.400, 0.000, 0.000)`
- **캡 홈 위치 `cap_home` = 월드 `(0.400, 0.000, 0.215)`** ← 관측 계산에 반복 사용
- 캡 반경 44mm, 캡 높이 16mm (캡 상면 z ≈ 0.231)
- 실물 지그가 다른 위치면 이 상수만 바꾸면 된다(단, 학습과 상대 배치가 크게 달라지면 성능 저하).

### 1.3 DOF 순서 (22) — **URDF 파일 순서와 다르다**
```
 0 base       1 shoulder   2 elbow      3 wrist1     4 wrist2     5 wrist3    (RB5 J1..J6)
 6 joint_0.0  7 joint_1.0  8 joint_2.0  9 joint_3.0     ← 검지 index
10 joint_12.0 11 joint_13.0 12 joint_14.0 13 joint_15.0 ← 엄지 thumb
14 joint_4.0  15 joint_5.0  16 joint_6.0  17 joint_7.0  ← 중지 middle
18 joint_8.0  19 joint_9.0  20 joint_10.0 21 joint_11.0 ← 약지 ring
```
URDF는 joint_0..15를 숫자순으로 선언하지만 IsaacGym은 **검지→엄지→중지→약지** 순으로 잡는다.
이 순서를 틀리면 엄지와 중지가 바뀐다.

### 1.4 "손목"의 정의
관측의 손목은 **Allegro 팜 베이스 링크 `base_link`** 다 (RB5 `tcp` 아님).
FK로 이 링크의 월드 위치·자세·선속도·각속도를 얻어야 한다.

### 1.5 손 링크 21개 순서 (obj_to_joints 용)
```
base_link,
link_0.0, link_1.0, link_2.0, link_3.0, link_3.0_tip,        (검지)
link_12.0, link_13.0, link_14.0, link_15.0, link_15.0_tip,   (엄지)
link_4.0, link_5.0, link_6.0, link_7.0, link_7.0_tip,        (중지)
link_8.0, link_9.0, link_10.0, link_11.0, link_11.0_tip      (약지)
```

## 2. 제어 루프

- **주파수 60Hz** (dt = 1/60 s). 에피소드 = **360스텝 = 6.0초**.
- 매 스텝: 상태 읽기 → 관측 조립 → 정규화 → 정책 → 액션 후처리 → 위치목표 전송 → 16.67ms 대기
- 학습에 **지연 모델이 없다**. 실물 통신/서보 지연이 크면 진동할 수 있으니 초기엔 액션 스케일을 줄여 시작할 것.

## 3. 관측 (총 200 = privileged 60* + proprioception 76 + target 65)

\* privileged 는 학습 시 60채널(critic 전용 저항 채널 포함). **actor 는 앞 22(dq)만 사용**하므로
로봇은 dq 22 + 나머지 38개 자리를 0 으로 채우면 된다.

정책 입력은 dict이며, 인코더가 **키 이름 사전순**으로 concat한다:
`privileged(60) ‖ proprioception(76) ‖ target(65)`.

### 3.1 privileged (59) — actor는 앞 22만 쓴다
| 인덱스 | 내용 | 실물에서 넣을 값 |
|---|---|---|
| 0:22 | 관절 각속도 `dq` (rad/s), §1.3 순서 | **엔코더 미분/속도 피드백** |
| 22:60 | (학습 때 critic 전용: 캡 상태·저항 등) | **0으로 채운다** — 네트워크가 actor 경로에서 이 구간을 지운다 |

> 주의: 마스킹은 **정규화 이후** 네트워크 내부에서 일어난다. 배포 시 학습과 동일한 네트워크
> 코드를 쓰면 22:59에 무엇을 넣든 무시된다. 직접 재구현한다면 그 구간을 **0(정규화 후)** 로
> 만들어야 하며, 원시값으로 넣는다면 체크포인트의 running mean 값을 넣어야 등가다.
> 가장 안전한 방법은 **학습 코드의 네트워크 forward를 그대로 이식**하는 것.

| 22:44 | `cos(q)` | |
| 44:66 | `sin(q)` | |
| 66:70 | 손목 자세 쿼터니언 **xyzw** | FK(`base_link`), 월드 |
| 70:73 | 손목 선속도 (m/s) | FK 야코비안 × dq, 또는 위치 차분(60Hz) |

(학습에서 손목 **위치**는 관측에 넣지 않는다. 컴팩트 빌드에서 아예 차원 제거됨.)

### 3.3 target (66)

| 3:6 | `delta_wrist_vel` | `0 − v_wrist` = **−v_wrist** |
| 6:10 | `delta_wrist_quat` | `quat_mul(q_wrist_now, quat_conj(q_wrist_ref))` — **현재⊗기준⁻¹**, xyzw |

```
wrist_pos_ref  = (0.38492, -0.01295, 0.33107)      # m, 월드
wrist_quat_ref = (-0.5116, -0.4730, 0.5499, -0.4605)   # xyzw  (부호 규약 주의: 학습 값 그대로 사용)
```

| idx | 채널 | 계산 |
|---|---|---|

**A91 과의 차이**: 풀림각·각속도 채널이 없다. 캡 상태를 정책이 전혀 모르는 대신,
보상 설계(낙하벌 완화 + 완주 보너스 강화)로 완주와 큰 손목 롤을 유도했다.

### 3.5 cap_tip_force6 (24) = target[41:65] — FSR
**인덱스 = 41 + 6×손가락 + 존.** 손가락 순서 **[0]엄지 [1]검지 [2]중지 [3]약지**,
존 순서 **[중앙-원위, 중앙-근위, −y-원위, −y-근위, +y-원위, +y-근위]**
(원위 = 손톱쪽, 근위 = 손가락 안쪽. 팁 링크 로컬 +x가 패드 법선.)

패드 존 기하(팁 링크 로컬, m):
```
중앙: (0.0105, 0, -0.0005), (0.0105, 0, -0.0155)          법선 (1, 0, 0)
-y : (0.0057, -0.0109, -0.0005), (0.0057, -0.0109, -0.0155)  법선 (0.6494, -0.7605, 0)
+y : (0.0057, +0.0109, -0.0005), (0.0057, +0.0109, -0.0155)  법선 (0.6494, +0.7605, 0)
```

**신호 처리 파이프라인 (반드시 동일하게)**
1. 각 존의 **수직 압력을 뉴턴(N)** 단위로 환산 (FSR 캘리브레이션 필요)
2. **EMA 저역통과**: `ema ← ema + 0.3 × (F − ema)` (60Hz, α=0.3). 에피소드 시작 시 0
3. **양자화**: 경계 `[1, 2, 3.5, 5, 6.5, 8.5, 11, 15, 21]` N → 레벨 0~9 → **출력 = 레벨/9**

   **레벨 = 경계값 중 F 보다 작은 것의 개수** (`torch.bucketize(F, edges)` 와 동치, 경계값과 같으면 아래 칸).
   ```
   F ≤ 1 → 0 |  1<F≤2 → 1 |  2<F≤3.5 → 2 |  3.5<F≤5 → 3 |  5<F≤6.5 → 4
   6.5<F≤8.5 → 5 |  8.5<F≤11 → 6 |  11<F≤15 → 7 |  15<F≤21 → 8 |  F>21 → 9
   ```
   예: 4.2N → 레벨 **3** → 3/9 = 0.333.  1.0N → 레벨 **0** (경계값은 아래 칸).

## 4. 관측 정규화

체크포인트에는 **키별 RunningMeanStd**(privileged/proprioception/target)가 저장돼 있다.
```
y = clamp((x − mean) / sqrt(var + 1e-5), −20, 20)
```
- 키마다 별도 통계를 쓴다. 반드시 체크포인트에서 로드할 것.
- NaN/Inf 는 `nan→0, +inf→+5, −inf→−5` 로 치환.
- 컴팩트 빌드라 상수 채널이 제거돼 있어, 예전 빌드에서 문제였던 "상수 채널의 316배 증폭"은 없다.

## 5. 정책 → 관절 명령

정책 출력 = **22 float** (팔 6 먼저, 손 16), 활성함수 없음.

```python
a = clamp(policy_out, -1, 1)

# 1) 가속(슬루) 제한 — 정규화 액션 공간에서
dv = zeros(22); dv[:6] = 50*dt*dt/0.02;  dv[6:] = 50*dt*dt/0.05     # dt = 1/60
a  = clamp(a, a_prev - dv, a_prev + dv);  a_prev = a                  # 리셋 시 a_prev = 0

# 2) 관절 증분
scale = [0.02]*6 + [0.05]*16          # rad/step (팔 1.2 rad/s, 손 3.0 rad/s 상한)
dq_cmd = a * scale

# 3) 적분형 목표 + 리쉬 + 관절한계
tgt = prev_target + dq_cmd
tgt = clamp(tgt, q_meas - 0.15, q_meas + 0.15)     # ±0.15 rad 리쉬 (지연 아님, 접촉 시 과부하 방지)
tgt = clamp(tgt, joint_lower, joint_upper)          # URDF 한계
prev_target = tgt
send_joint_position_targets(tgt)                    # 절대 각도(rad)
```

저수준 PD (sim 기준값 — 실물 컨트롤러에 맞게 환산):
| 축 | stiffness | damping | effort |
|---|---|---|---|
| 팔 0~5 | 4000 | 160 | 150,150,150,28,28,28 N·m |
| 손 6~21 | 300 | 18 | 0.7 N·m |

**루프가 유지해야 할 상태**: `prev_target`(22), `a_prev`(22), `step`, FSR EMA(24),
J6 누적(1), J6 직전값(1), released 래치(1).

## 6. `released` 추정기 (실물에서 만들어야 하는 유일한 항목)

캡이 나사에서 풀려 자유가 됐는지를 0/1 래치로 넣는다. 후보:
- **회전 저항 급감**: 팔 관절 토크(또는 전류)의 회전 성분이 임계 이하로 떨어지고 유지될 때
- **FSR 패턴 변화**: 해제 순간 접촉력 분포가 급변
- **비전이 있다면**: 풀림각이 해당 텀블러의 해제 각도에 도달하면 1 (가장 확실)
- 최후: 목표 회전에 해당하는 시간/손목 누적각으로 근사
오검출(너무 이른 1)이 더 위험하니 임계는 보수적으로.

## 9. 알려진 위험

| 위험 | 내용 | 완화 |
|---|---|---|
| FSR 캘리브레이션 | 양자화 경계가 N 단위라 물리 단위 보정이 필수 | 힘 게이지로 존별 보정 곡선 작성 |
